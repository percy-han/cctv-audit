# 门店远程 CCTV 视频智能抽检专用 Agent (Google ADK & Computer Use)

本项目基于 Google **Agent Development Kit (ADK 2.0)** 与 **Gemini Computer Use** 协议构建，专为**连锁门店远程 CCTV 监控视频智能抽检**场景打造。

你只需在 **ADK Web UI** 中提供一段监控视频页面链接，Agent 即可自主操控浏览器进入播放页面、开启视频播放、针对约 1 分钟时长的作业画面进行分段抽检与视觉行为理解。抽检过程中，每一段视频画面内容分析与 SOP 判定会**实时上屏显示在监控画面的右侧边栏**，并在抽检结束后输出完整的分段审计表格与**不符合 SOP 标准的问题清单**。

## 🌟 核心功能与特色

### 1. 📹 门店视频自主定位与分段抽检
- **自主定位与播放**：Agent 访问目标视频页面后，自动识别播放器并执行开始播放、展开全屏或调整视角。
- **1 分钟微观抽检协议**：默认以约 10~15 秒为一个观测步长（或依关键操作节点分段），连续抽检 1 分钟内的员工作业全流程。
- **逐段画面内容理解**：精确识别画面中的操作员工、操作台面、器具、物料以及具体动作。

### 2. 📺 双屏监控与右侧边栏实时上屏 (`http://127.0.0.1:8080`)
在监控服务页面，左侧为 Playwright 的 CDP 实时画面推流与 AI 鼠标雷达高亮，**右侧边栏提供专用的 CCTV 巡检工作台**：
- **📹 视频分段巡检 (Segments)**：视频每分析完一段（例如 `[00:00 - 00:15]`），**立即推送至右侧边栏**，显示时间区间、画面内容详细描述及合规徽章（合规 / 违规 / 无法判定）。
- **⚠️ SOP 违规清单 (SOP Issues)**：自动归集所有不符合 SOP 的违规行为，标红展示并提供一键复制功能。
- **🛠️ 动作序列 (Actions)**：记录 Agent 操控浏览器的原子动作（如 `click_at`、`wait`、`navigate` 等）。
- **🧠 AI 推理 (Reasoning)**：实时展示 Gemini 的多模态视觉推理链与观察细节。
- **📑 最终报告 (Final Report)**：抽检完成后自动排版输出完整的 Markdown 审计报告。

### 3. 📋 内置门店运营标准（SOP）审查红线
Agent 系统内置了茶饮/零售门店常见的核心规范体系，抽检时重点审查以下维度：
1. **着装与仪容规范（CHK_ATTIRE_001）**：工作服规范穿戴、工帽正确佩戴包裹头发、口罩遮盖口鼻。
2. **手部卫生与手套管理（CHK_HYGIENE_002）**：接触即食原料或杯口前洗手/戴食品级一次性手套，手套破损或触碰非洁净物后及时更换。
3. **器具使用与清洁（CHK_TEA_001）**：雪克杯、量杯用后立即冲洗，洁具与食品器具严格分区。
4. **吧台/操作台面卫生（CHK_SANITATION_003）**：台面无溢液、积水、废弃茶渣或散落包材，毛巾专用分区。
5. **作业纪律与行为规范（CHK_BEHAVIOR_004）**：吧台操作期间禁止玩手机、脱岗聊天、饮食或在原料上方咳嗽等。

### 4. ⚡ 7×24 小时全天候长视频巡检与防爆机制
针对长视频监控与 24 小时不间断挂机巡检，系统内置了五重高可用防护：
- **$O(1)$ 上下文滚动滑动窗口（Rolling Context Compaction）**：历史轮次动态压缩为带当前进度的“工作记忆快照”，对话轮次永不超限，Token 规模恒定保持在 3k~5k，调用延迟始终极速，彻底杜绝大模型 Context Window 溢出。
- **Chromium 深度内存防爆限制**：
  - 强制限制 V8 堆内存上限：`--js-flags=--max-old-space-size=512`，强制 V8 积极垃圾回收。
  - 禁用音频流解码：`--mute-audio`，消减监控视频流在 Chromium MSE 缓冲区的 CPU 与内存消耗。
  - 磁盘与媒体缓存强制封顶：`--disk-cache-size=10485760` (10MB)。
  - 定期主动触发 V8 Garbage Collection（每 25 轮自动清理 JS 内存）。
- **CDP 实时推流防爆限频**：WebSocket 帧率智能压制至 ~4 FPS，分辨率智能降噪，杜绝长时运行导致的前后端内存暴涨。
- **本地 Checkpoint 实时落盘**：所有分段与违规记录同步写入 `computer_use_agent/checkpoints/audit_records.jsonl`，支持断电断线后无感续检。
- **页面崩溃自愈守护（Self-Healing）**：实时监测 `Page.is_closed()` 与 Chromium 心跳，发生偶发闪退或网络重连时自动原地自愈。

### 5. 🛡️ Google Cloud 原生鉴权与高可用架构
- **Google Cloud Vertex AI 授权**：使用 Google Cloud ADC / gcloud 鉴权，**无需任何 API Key**。
- **动态截帧修剪**：自动对多轮对话的历史截帧进行剪裁（仅保留最新 2 帧高清截图），避免 Payload 膨胀（>40MB）及跨区路由 400 报错。
- **双轨分段捕获机制**：同时支持 Function Calling（`record_video_segment`）和正则推理文本抽取，确保 100% 捕获每一分段并实时推送到监控大屏。

```text
│   └── .env                         # GCP 项目环境配置（Project ID, Location, Model）
└── README.md                        # 项目说明文档
```

## 🚀 快速启动指南

### 1. Google Cloud 授权确认

确保当前终端已完成 Google Cloud 鉴权：

```bash
# 登录你的 Google Cloud 账号
gcloud auth login
gcloud auth application-default login

# 设置使用的 GCP 项目 ID
gcloud config set project <your-project-id>

# 配置 .env 文件
cp computer_use_agent/.env.example computer_use_agent/.env
# 配置其中的 project-id
```

在项目根目录下执行：


- **💬 ADK Web 对话控制台**：`http://127.0.0.1:8000/dev-ui/`
- **📺 CCTV 实时抽检监控大屏**：`http://127.0.0.1:8080/`

## 🎯 使用示例（CCTV 视频抽检）

1. 在浏览器中打开 **http://127.0.0.1:8080**（建议分屏或放置在右侧窗口查看画面推流和右侧分段卡片）。
2. 在浏览器中打开 **http://127.0.0.1:8000/dev-ui/**，在 Agent 列表中选择 `computer_use_agent`。
3. 在对话框中输入抽检指令，例如：

### 抽检指令示例：
```text
请帮我抽检这段门店监控视频：
https://www.bilibili.com/video/BV1GJ411x7h7

抽检要求：
1. 访问该页面并定位到视频播放区域，确保视频处于播放状态。
2. 对视频前 1 分钟内容进行抽检，按 10-15 秒左右细分时间段。
3. 将每小段（几分几秒到几分几秒）画面中的员工操作内容实时记录到右侧监控面板。
4. 严格对照门店 SOP 标准（着装口罩、手部手套、器具清洁、台面卫生、行为纪律）进行合规审查。
5. 抽检完成后，输出完整的分段审计表格，并列出不符合 SOP 标准的问题清单。
```

## ⚙️ 常见问题与排障 (FAQ)

- **Q: 为什么右侧边栏没有看到新分段？**
  - A: 确保在浏览器中打开了 `http://127.0.0.1:8080/` 且 WebSocket 显示为绿色 `Connected`。Agent 无论通过 Function Calling 还是文本输出时间区间，都会自动触发并追加卡片。
- **Q: 遇到 400 INVALID_ARGUMENT (Computer Use not supported in this region) 怎么办？**
  - A: Vertex AI 的 Computer Use 特性目前部署在 `location="global"`，请确保 `.env` 中的 `GOOGLE_CLOUD_LOCATION=global`，模型选用 `gemini-3.5-flash`。
- **Q: 监控视频播放卡顿或截图加载较慢？**
  - A: 监控大屏通过 Chrome DevTools Protocol 截帧推流（约 5 fps），建议在网络良好环境下运行，并保持浏览器视窗尺寸为默认的 1280x800。
